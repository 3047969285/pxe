# 规则引擎与建议名单

## 一、怎么用

```bash
node index.js 名单 --年度 2027                  # 一条命令：按状态自动推进，照提示做
node index.js 规则 登记                         # 模型翻译好草稿后
node index.js 规则 确认 "<审核表.xlsx>"         # 用户审核完后
node index.js 名单 --复现 "<运行记录.json.gz>"  # 核对某次名单可复现
node index.js 看板 --年度 2027                  # 统计看板
```

产物落在「输出」文件夹：审核表、建议名单 Excel（3 个工作表）+ HTML、运行记录、看板 HTML；
规则译文与审核状态在「输出/规则解析/规则译文库.json」。

## 二、规则从哪来

规则全部由用户自定义上传，**数据库只存规则原文，不存也不读任何建议名单**。一个年度的条款有三类：

| 来源 | 表与列 | 生效范围 |
|---|---|---|
| 通用规则 | 规则表「规则内容」 | 本年度全部期次 |
| 计划·参培对象 | 计划表「参培对象」 | 只对该期次 |
| 计划·调训规则 | 计划表「调训规则」 | 只对该期次 |

原文相同的期次（如进修班第一到四期）共用一个条款，只翻译、审核一次。

## 三、文字怎么变成筛选条件（识别 → 审核 → 锁定）

```
条款原文 → 模型按 rule_dsl.md 翻译成受限条件 → 规则 登记（严格校验，待审核）
→ 规则 审核表（用户逐条 确认/修改/驳回）→ 规则 确认（已确认，锁定）
→ 建议：逐期次 准入/剔除 → 加分 → 固定排序 → 按名额取数
```

- **模型负责灵活理解**：按句拆分原文，判断是准入、剔除还是加分，用固定的字段、指标、运算符拼成条件；
  库里没有对应数据的句子列为「未识别」并写明原因，不硬凑。
- **用户负责拍板**：审核表里每行一个条件，带中文复述和试算影响人数；可以直接改条件，也可以驳回写意见。
- **确认后锁定**：每个条款按原文算指纹，已确认的译文之后任何模型都复用，名单逐行一致；
  原文改一个字指纹就变，自动回到待翻译，**只有变化的条款需要重新审核**。
- 有任何条款未确认，`名单` 不出名单，而是写草稿或出审核表，并打印下一步。

## 三之一、一致性与复现

| 保证 | 怎么做到 |
|---|---|
| 不同模型出同一份名单 | 名单只由「接口数据 + 已确认条款」计算；模型只参与翻译，翻译结果必须人工确认后才生效，确认后按指纹锁定 |
| 同样输入结果逐行一致 | 期次、人员、条款、并列名次都按固定键排序，与接口返回顺序无关 |
| 每次用最新数据 | 每次 `名单` 都从接口重新拉取五张表，不用缓存 |
| 过程可复现 | 每次出名单写 `运行记录_年度.json.gz`：数据指纹、规则指纹、代码指纹、结果指纹 + 输入快照（不含身份证号）；`名单 --复现` 重算核对 |

翻译规范、字段、指标、运算符、标准默认值见 [规则识别与人工审核](rule_dsl.md)。

## 四、算出来的名单包含什么

| 工作表 | 内容 |
|---|---|
| 建议名单 | 每个班次期次建议谁去：单位、姓名、级别、累计学时、评分、优先级、推荐理由 |
| 剔除与顺延 | 有名额单位里谁被剔除、哪个条款、什么原因；名额满了的记「顺延」 |
| 按期次汇总 | 每期计划人数、建议人数、剔除人次 |

命令行同时打印每个条款的生效人次和未执行的句子，便于核对。

## 五、内置译文

技能自带示例数据里 7 条通用规则和 10 段计划规则的译文（`scripts/rule_presets.json`）。
原文不变时不用翻译，但**仍须经审核表确认后才生效**。

## 六、规则怎么配置

通用规则在 `pxe_training_rule` 表维护（模板：`templates/培小e-通用规则导入模板.xlsx`）：

| 列 | 说明 |
|---|---|
| 规则类型 | 硬规则 或 软规则 |
| 规则名称 | 如「硬规则一：AB角不得同出」 |
| 规则内容 | 写明判定条件，数字、日期、班次名写具体 |
| 是否启用 | 填 1 启用、0 停用；留空视为启用 |

计划规则直接写在培训计划表的「参培对象」「调训规则」两列。
导入或修改规则、计划后，直接跑 `名单 --年度 2027`，它会只让变化的条款重新翻译和审核。

## 七、停用规则

把「是否启用」改成 `0` 即可停用，改回 `1` 恢复；原文没变的话已确认的译文仍有效，无需重审。
