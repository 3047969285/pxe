# 故障排查

按现象找原因。排查顺序：**先测连通 → 再看文件 → 最后看数据**。

## 一、先做连通性自检

```bash
node index.js 查询 规则 --每页 1
```

- 返回数据 → 后端通，问题在文件或数据；
- 报 `fetch failed` → 后端不通，见下一条。

## 二、按现象排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `fetch failed` / 连接被拒 | 后端服务没起，或地址不对 | 确认后端已启动；核对 `scripts/config.js` 的 `api.baseUrl`（形如 `http://IP:7529/api/HuangDao/training`） |
| HTTP 401 `未授权` | `apiSecret` 与后端不一致 | 把 `config.js` 的 `api.apiSecret` 改成与后端 `app.api-secret` 完全一致 |
| `身份参数不完整` / `身份校验失败` | 请求里没带凭据，或凭据不对 | 用默认管理员执行；或 `--credential` 传对身份证后四位 |
| `不支持的查询字段 xxx` | 字段名写错 | 对照 [字段对照表](field_mapping.md) 改写 |
| `未解析到有效数据行` | 表头没被识别 | 核对表头写法；或加 `--sheet <工作表名>` 指定；或加 `--table <表>` 显式指定表 |
| `第 N 行缺少必填字段` | 该行必填列为空 | 脚本会跳过该行并提示，其余行照常导入；补上后再导一次即可 |
| `未匹配到培训计划` | 导入顺序错，或班次名称不一致 | **先导培训计划再导名额/记录**；核对班次名称与计划表一致 |
| `数据对象与数据表不一致` | 请求里的数据对象与 `table` 不匹配 | 检查是否混用了不同表的字段 |
| `单条数据与批量数据只能提交一种` | 同时传了单条和批量 | 只传其中一种 |
| `修改必须提供记录标识` 之类 | 缺主键 | 补上主键字段（见 [命令全集](commands.md)） |
| `分页偏移过大` | 页码太靠后 | 缩小页号，或加条件缩小范围 |
| 导出/模板报「写入 Excel 失败」 | 目标目录不可写或文件被占用 | **关闭正在打开的 Excel 文件**；确认「输出」文件夹可写 |
| `名单` 退出码 2 / 3 | 有条款待翻译（2）或待审核（3），不是错误 | 照它打印的「第 N 步」做 |
| `改` / `删` 报「命中 N 条」或「没有找到」 | 定位字段不够或写错 | 补全定位字段（见 [命令全集](commands.md) 修改与删除），先加 `--预览` 看 |
| `规则 确认` 报「没填审核人」/「不在允许名单」 | 审核表里该条款没填审核人，或不在 `review.reviewers` 里 | 由审核人本人填写姓名后保存 |
| `规则 确认` 报「审核单号无效」/「已经确认过」 | 用的不是系统签发的审核表，或同一张表重复确认 | 重新运行 `名单` 生成新的审核表 |
| 出名单时提示「审核疑点」 | 审核表不是用 Excel/WPS 保存的、或审核用时过短 | 用 `规则 审计` 查看；确属本人审核可忽略，否则让审核人重新审核 |
| 已确认的条款又变回待审核 | 译文库或审核日志被手工改过 | 用 `规则 审计` 查看原因，重新审核该条款 |
| `名单 --复现` 不一致 | 代码指纹变了（技能升级）或运行记录被改过 | 代码指纹不同时属正常；否则联系维护人员 |
| `自检` 提示人员接口未返回任职时间 | 后端表枚举没加 `hireDate` | 请后端把 hire_date 加进人员表的接口字段 |
| `规则 登记` 报「译文未通过校验」 | 用了目录外的字段/键、动作与规则类型不符、数值加了引号等 | 按每行报错逐条改草稿再登记；一条不过全部不登记 |
| `规则 登记` 报「已经人工确认」 | 该条款已确认 | 不需要再译；用户明确要求改译时加 `--覆盖`（会退回待审核） |
| `规则 确认` 报「审核表有问题」 | 改条件时字段写错、分支号缺失、审核结果填了别的词等 | 按报错的行号改审核表后重新确认；一条有问题全部不保存 |
| `规则 确认` 报「不属于当前条款」 | 生成审核表后规则或计划原文又改了 | 重新生成审核表再审 |
| 审核表打不开 / 读不出 | 缺 openpyxl，或审核表被改了工作表名 | `自检` 检查 Excel 环境；用 `规则 审核表` 生成的文件，不要改「审核」工作表名和表头 |
| `班次类别配置有误` | 草稿里的班次类别表格式不对 | 对照 [规则翻译约束](rule_dsl.md) 第六节 |
| 图表不显示 | 缺 `echarts.min.js` | 确认产物的同目录有 `echarts.min.js`（生成时会自动复制一份） |
| 打开 HTML 是空白 | 数据没取到 | 确认后端在跑；HTML 里的数据是生成时取好的，重新生成一次即可 |

## 三、进阶排查

| 想看什么 | 怎么做 |
|---|---|
| 全部命令 | `node index.js 帮助` |
| 某个文件能识别成什么表 | `python scripts/excel_parser.py "<文件>" --info` |
| 某文件的表头映射情况 | `python scripts/excel_parser.py "<文件>" <表名> --headers` |
| 直接看接口契约 | 打开 [接口契约](api_contract.md) |
| 结果目录里有什么 | 查看技能包同级的「输出」文件夹 |

## 四、设计上不会发生的问题（不必排查）

技能**不会**：直连数据库、执行 SQL、改后端文件、往别处写文件、产生过程文件、
把重复数据写进去（全部 UPSERT）。遇到这些现象说明执行的不是本技能包的命令。
